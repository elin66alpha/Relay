### Desktop Web file browser can stay on "Reading files..."

On desktop Web (1440x960, Chromium), opening **File system** from the drawer
sometimes stays on **正在读取文件... / Reading files...** forever; pressing
**Refresh** loads the list at once. The same flow on a mobile viewport works,
and `GET /api/workdir/browse` answers in about 10 ms, so the backend is not
the cause.

- Not reproduced. A stalled request is not the cause: every request in
  `ApiTransport` times out after 20 s and the screen then shows an error, and
  Refresh is disabled while the screen is loading. A Refresh that responds
  means the load had already finished and the page had not been repainted.
  Flutter Web paints only on the browser's animation frames, which a hidden
  or background tab does not run, so the capture tool's tab is the first
  suspect. Next step: reproduce in a foreground tab before changing code.
- Found while taking screenshots against the demo backend.
