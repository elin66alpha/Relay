## To fix

### Claude Code always shows "Log in again within a day"

Machine details shows **今天之内需要重新登录 / Log in again within a day** under
Claude Code even though the login is fine.

- Cause: `claudeCredential` in `server/lib/agent-status.js` reports
  `claudeAiOauth.expiresAt` as `credentialExpiresAt`. That is the expiry of the
  short-lived access token (it was 4.1 hours away when checked on 2026-10-19),
  which Claude Code and `server/lib/usage.js` refresh automatically with the
  refresh token. It is not a login deadline, so it is almost always under a day
  and the warning almost never goes away.
- Direction: treat it like Codex: no login deadline while a refresh token
  exists. Update the matching line in `AGENTS.md` ("reads ... Claude's
  `credentialExpiresAt`") and the client expiry tests along with the fix.

### Desktop Web file browser can stay on "Reading files..."

On desktop Web (1440x960, Chromium), opening **File system** from the drawer
sometimes stays on **正在读取文件... / Reading files...** forever; pressing
**Refresh** loads the list at once. The same flow on a mobile viewport works,
and `GET /api/workdir/browse` answers in about 10 ms, so the backend is not
the cause.

- Not yet confirmed. `_loadInitial` / `_browse` in
  `lib/features/filesystem/file_system_screen.dart` have no timeout, so any
  request that stalls leaves the spinner up. One lead: the desktop layout holds
  more long-lived connections (SSE), which could exhaust the browser's
  six-connections-per-host limit on HTTP/1.1 and queue the request.
- Found while taking screenshots against the demo backend.
