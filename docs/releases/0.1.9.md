# Relay 0.1.9

Relay 0.1.9 adds Cursor as a fifth agent and tidies the model picker. This
release includes Android and Windows clients, the source backend setup bundle,
and a Windows backend bundle with its own Node.js runtime.

## Highlights

- **Cursor joins Relay:** Cursor appears in the agent list below Codex. Once
  the host's `agent` CLI is signed in (`agent login`, or `CURSOR_API_KEY`), you
  can pick its model, reasoning effort, Fast mode and permission like Claude
  Code and Codex, with several Cursor sessions running at once. Relay's Cursor
  uses its own config directory, `server/cursor-config/`, so choices made in
  Relay never change the host's Cursor defaults. Quota Usage shows Cursor's
  included usage.
- **A tidier model list:** main models come first. Cursor models billed outside
  the plan, and older Claude Code and Codex models, move to a second page
  opened from the bottom of the screen. Swarms list main models only.
- **Current OpenCode and Hermes models:** OpenCode's list comes from the host's
  `opencode models`, including every provider configured there. Hermes gains a
  Model entry showing the model configured on the host.

Other changes:

- Machine details has a hardware card: CPU, memory and GPU names, disk usage,
  and live temperatures where the host exposes them.
- Linux setup checks the Node.js version and, on Debian and Ubuntu, offers to
  install missing prerequisites with `sudo apt-get`.
- The source backend setup bundle includes the Web client, served at the
  backend address (turn it off with `RELAY_SERVE_WEB=0`). Linux `setup.sh` is
  now a menu: install, reinstall, uninstall, service status, and creating,
  deleting, listing or re-showing device tokens. The Windows backend bundle
  has no Web client, and only Linux setup asks about the Web client or removes
  it on uninstall.
- Claude Code no longer shows a false "log in again within a day" warning on
  Machine details.
- OpenCode, Hermes and Cursor start a new message after each tool call, as
  Claude Code and Codex do.
- Relay approves Cursor actions once only, so it no longer adds commands to the
  host user's own Cursor allowlist.
- Deleting or clearing a Cursor conversation also deletes its session record.
- The file API refuses Cursor's `auth.json`, like the Claude Code and Codex
  credential files.
- The backend finds agent CLIs installed in `~/.local/bin` (Claude Code, Codex
  and others) even when its service PATH lacks that directory.
- Switching to another backend reloads that host's agent list instead of
  keeping the previous backend's install and sign-in status.
- Machine details no longer splits words across two lines on portrait phones.

See the [changelog](https://github.com/elin66alpha/Relay/blob/v0.1.9/CHANGELOG.md)
for the complete change list.

## Windows setup

The Windows client and bundled Windows backend have been rebuilt together from
[`473ca69`](https://github.com/elin66alpha/Relay/commit/473ca69356d5c9c155b80cad8c43cf61b9543318)
on the `0.1.9` branch. These downloads replace the earlier Windows ZIPs under
the same filenames; the desktop application still reports `0.1.9+19`.

This Windows refresh adds the Machine details hardware card: CPU model and
thread count, memory, GPU names, used/total capacity for each readable local
disk, and available temperatures refreshed every 10 seconds while the page is
open. Windows temperatures come from `nvidia-smi` when available; the page
otherwise reports that no temperature sensors are readable. It also retains
the upload-cleanup fix and all Cursor features included in the previous build.

This Windows rebuild replaces the two Windows ZIPs. Android and source setup
downloads are maintained independently.

For the desktop client, extract the whole client ZIP and run `relay.exe`.
Keep the executable, DLLs, and `data` directory together.

For the backend:

1. Extract the entire backend ZIP to a permanent, writable directory. Keep
   `server`, `backends`, and `runtime` together.
2. Install and authenticate/configure at least one agent CLI on the host:
   Claude Code, Codex, Cursor, OpenCode, or Hermes. Cursor uses the `agent`
   executable and signs in with `agent login`. Install `cloudflared` separately
   if choosing a Cloudflare tunnel.
3. Open PowerShell in the extracted backend directory and run:

   ```powershell
   .\setup.cmd
   .\status.cmd
   ```

4. Choose the port, network mode, and credential passphrase. Import the generated
   `.relay.json` or `.relay.png` from `server/credentials` in the Relay client.

Node.js, npm, and backend dependencies are included. Setup creates a Scheduled
Task for the current user's login. The backend ZIP contains no deployment
state, agent credentials, Cursor config, or compiled Flutter client.
Use HTTPS for public access. Quick Tunnel URLs can change after restart;
regenerate and import a credential if that happens.

Manage the backend from its extracted directory:

```powershell
.\start.cmd
.\stop.cmd
.\status.cmd
.\credential.cmd --url https://YOUR-BACKEND
.\uninstall.cmd
```

Uninstall stops Relay and removes its login task, retaining configuration,
credentials, and history. Read the bundled README for updates and log locations.

## Known issue

On desktop Web, opening **File system** from the drawer can occasionally stay
on **Reading files...**; pressing **Refresh** loads the list at once. It has
not been reproduced in a foreground browser tab.
